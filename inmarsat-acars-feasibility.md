## Update 2026-07-22 — corrections + multi-band framing

Re-reviewed alongside a whole-band ACARS feasibility pass (VHF/VDL2/satellite/HF).
Corrections to the original doc below:

- **Is it worth it (with the antenna + filter)? Yes — for one specific reason.**
  Inmarsat Aero is the only band that yields **oceanic/remote ADS-C position
  reports and CPDLC** (controller–pilot datalink) that VHF and Iridium can't give
  you — plus plain SATCOM ACARS. That's the differentiator. Plain ACARS text works
  day one; the ADS-C/CPDLC payloads ride ARINC-622 and need the **libacars ASN.1
  sub-decoders that `common/libacars_idf/CMakeLists.txt` deliberately stubs out**
  (~242 ASN.1 files, NOT compiled) — enabling them is a flash-size + porting
  exercise (the 12 MB app partition likely absorbs it). So: useful, with real
  content, but the *best* content is gated behind that sub-decoder work.
- **Viterbi is NOT something to avoid.** The original MVP scoped out the 10.5 kbps
  OQPSK channel to dodge a Viterbi decoder. On the P4, rate-1/2 k=7 Viterbi at
  ≤10.5 kbps is ~0.7 M ACS ops/s — trivial. Include 10.5k from the start if the
  content warrants; compute is not the constraint (Iridium's 25 ksym/s QPSK is far
  heavier and already runs).
- **Licensing concern is MOOT.** The old doc worried that pulling GPL-3
  inmarsat-sniffer would "force GPL-3 on the whole firmware." libacars (GPL-3) is
  **already** vendored and linked (`common/libacars_idf`), so the firmware's
  distribution posture is already GPL-3. Porting from inmarsat-sniffer/JAERO adds
  no new constraint. Use the cleanest reference (inmarsat-sniffer).
- **MTSAT is dead** — satellites retired, Japanese oceanic SATCOM moved to
  Inmarsat/Iridium. Don't plan for it.
- **Horizon:** Classic Aero traffic is slowly migrating to SwiftBroadband-Safety /
  Iris, which has **no open decoder**. Aero value is real now but has a multi-year
  ceiling. Iridium Certus is likewise closed (the existing Iridium SBD path is the
  open slice).
- **Selection = NVS soft-switch, not a build flag.** Prefer one firmware with an
  NVS band profile (`band=iridium|poa|vdl2|aero`) over the original
  `CONFIG_INMARSAT_AERO_ENABLED` compile flag — flash/PSRAM budgets allow it and it
  fits OTA/bench workflow. **BUT note the RF-frontend caveat below:** the *software*
  soft-switches instantly (LO + sample-rate are already NVS); the *SAW filter*
  can't. Aero (1542 MHz SAW) vs Iridium (1620 MHz SAW) is a physical part swap —
  soft-switching between them cleanly needs a broadband L-band LNA (reduced
  selectivity) or a switched filter bank. A build flag remains a sensible hedge
  ONLY because Aero adds a *continuous-carrier ingest mode* (not the burst tagger),
  which is a bigger runtime branch than a VHF band-profile swap.
- **Antenna aim for Sydney (Southern hemisphere):** geostationary sats sit over the
  equator, so aim the patch **NORTH** with a clear northern sky — the original doc's
  "southerly sky view (Northern hemisphere)" is inverted for our location.
- The reception-environment heuristic + `band_health` survey machinery
  (2026-07-22) are band-agnostic and carry over; the burst tagger does NOT (Aero is
  a continuous carrier — see §4 "Detect").

## 1. Inmarsat ACARS Overview

Inmarsat carries aviation ACARS over the **Classic Aero** ("Aero H / H+")
protocol on top of Inmarsat's L-band SATCOM service. The forward link
(satellite → aircraft, the link an L-band ground station receives)
operates roughly **1545–1547 MHz**, with the lower-rate channels
clustered around 1545 MHz and the high-rate OQPSK channels around
1546 MHz ([sigidwiki](https://www.sigidwiki.com/wiki/Inmarsat_Aero),
[SDRplay L-band tutorial](https://sdrplay.com/resources/decoding_lband.pdf)).

Aero defines four logical channel types (P / R / T / C):

- **P-channel (forward, continuous TDM)** — 600 / 1200 bps **A-BPSK**
  ("aviation BPSK", behaves like MSK with sine-wave transitions) or
  **10.5 kbps OQPSK** with rate-1/2 k=7 convolutional FEC. This is the
  channel that carries forward ACARS, ADS-C and CPDLC, and it is
  **continuously broadcast** — no burst hunting needed.
- **R / T-channel (return, burst)** — TDMA bursts at the same
  modulations. These are aircraft-to-satellite, harder to receive on
  the ground (need C-band downlink reception).
- **C-channel** — voice (AMBE at 8.4 kbps).

Occupied bandwidth per P-channel is tiny: roughly 800 Hz at 600 bps and
~2 kHz at 1200 bps, scaling to ~10–20 kHz for the 10.5 kbps OQPSK
channels. One satellite's full Aero downlink fits comfortably inside a
few hundred kHz.

**Encryption:** roughly 99% of ACARS-over-Inmarsat is plaintext; what
little encryption exists is operator-applied, not Inmarsat-applied
([Oxford fc-paper.pdf](http://www.cs.ox.ac.uk/files/9693/fc-paper.pdf)).
This contrasts with the previous (incorrect) framing of "Iridium ACARS
is encrypted" — both Iridium and Inmarsat ACARS are decodable from
their respective L-band downlinks, and tools like
[iridium-toolkit](https://github.com/muccc/iridium-toolkit) and
[JAERO](https://github.com/jontio/JAERO) demonstrate this in practice.

## 2. Existing Decoders

| Project | License | Notes |
|---|---|---|
| [JAERO](https://github.com/jontio/JAERO) | MIT | Canonical reference, C++/Qt. Decodes 600/1200, 8.4k, 10.5k. Desktop-targeted. |
| [inmarsat-sniffer](https://github.com/alphafox02/inmarsat-sniffer) | **GPL-3.0** | JAERO chain forked, Qt-stripped, no GNU Radio, pure C++. **The most relevant prior art** — proves the DSP can run as a plain library. |
| [libacars](https://github.com/szpajder/libacars) | **GPL-3.0** | Decodes ARINC-622 / ARINC-620 application payloads (ADS-C, CPDLC, FANS-1/A). Already integrated with acarsdec / dumpvdl2 / JAERO. |

There is **no existing port to ESP32 / RP2040 / similar microcontrollers**.
Everything assumes Linux + ~hundreds of MB RAM.

## 3. Hardware Compatibility

**RTL-SDR v4** (24 MHz – 1.766 GHz) covers 1545 MHz with margin. The
forward Aero band is **continuous** — unlike Iridium there's no
per-burst frequency hopping across 50 channels — so you can park on
one carrier at a low sample rate (250 kHz–2.4 MHz). The existing
2.56 MS/s pipeline is overkill for Aero. This actually **reduces**
DSP load relative to Iridium.

**Antenna requirements are the real difference.** Iridium LEOs are
loud, ~780 km altitude; an omnidirectional QFH works. Inmarsat is
**geostationary at ~36,000 km**, much weaker. Required SNR for JAERO
Aero decoding is **>7 dB**.

- **RTL-SDR Blog active L-band patch** (1525–1660 MHz, RHCP, ~3.5 dBi
  + integrated LNA, ~$45) is the standard hobbyist solution and
  **covers both Iridium and Inmarsat** — no second antenna needed.
- 7-turn helix (~10–13 dBi) for marginal locations or reliable 10.5k.
- **Pointing:** geostationary → fixed aim once installed (easier than
  Iridium QFH in some respects), but requires a clear southerly sky
  view (Northern hemisphere).

**Filter / LNA — the gotcha.** The current **Nooelec SAWbird+ IR**
(centre 1620 MHz, 60 MHz BW) is **wrong for Aero** — won't pass
1545 MHz cleanly. Correct part is the **Nooelec SAWbird+ iO**
(centre 1542 MHz, ~80 MHz BW). Iridium and Inmarsat Aero are 75 MHz
apart, so **a single SAW filter cannot cleanly cover both** — supporting
both bands well requires either a wider/dual filter, switching between
SAWs, or accepting reduced selectivity using a broadband L-band LNA.
This is a non-trivial RF-frontend decision.

## 4. Effort Estimate

| Stage | Iridium today | Aero P-channel | Effort |
|---|---|---|---|
| RF tune | 1626 MHz, 2.56 MS/s, 50-channel scan | 1545 MHz, fixed carrier, ~250 kHz | Trivial (param + RF frontend swap) |
| Detect | 2048-pt FFT burst detector | Continuous carrier, sync-word lock | New, but simpler — no burst gating |
| Demod | DQPSK + PLL | A-BPSK / MSK (600,1200) **and/or** OQPSK (10.5k) | New DSP. MSK is genuinely different from DQPSK; OQPSK is similar |
| FEC | BCH(31,21) | Convolutional rate-1/2 k=7 + **Viterbi** | New. Well-known but not free in CPU/RAM on an MCU |
| Descramble + frame | Iridium-specific | Aero superframe + descrambler | New |
| Application | (limited today) | ARINC-618/620/622 → libacars | Reuse libacars |

**MVP scope (lowest-hanging fruit): 600/1200 bps P-channel only**, decoding
into raw ACARS frames. That's plenty of traffic and avoids Viterbi entirely.

| Sub-task | LOC | Hours |
|---|---|---|
| Port `MskDemodulator` + `AeroL` from inmarsat-sniffer | ~2–3 k | 60–100 |
| Add convolutional/Viterbi (for 10.5k) | ~1–2 k | 40–60 |
| libacars integration | — | 20–30 |
| Ground-truth corpus (run JAERO over same captures) | — | 5–10 |
| **MVP total (600/1200 only)** | **~4–6 k** | **~120–180 h** |
| **+10.5k OQPSK** | +1–2 k | +40–60 h |

## 5. Risk Areas

- **Spec accuracy.** Aero wire format is *not* fully open. JAERO and
  inmarsat-sniffer are reverse-engineered references, the de facto
  spec for hobbyist work. ICAO Annex 10 covers SARPs at a high level
  but not bit-exact superframe layout. Mitigated by tracking
  inmarsat-sniffer upstream.
- **RF frontend mismatch.** Current SAWbird+ IR (1620 MHz) is wrong
  for Aero. A user attempting Inmarsat with the existing filter sees
  severely attenuated signal. Either ship a dual-band frontend or
  document clearly that Inmarsat mode requires a different LNA/filter.
- **Sensitivity / antenna.** Geo-sat path loss is ~30 dB worse than
  Iridium; SNR margin is thin. Indoor reception possible but not
  guaranteed.
- **Legal.** Plaintext reception of public RF for personal use is
  broadly legal in the US (FCC) and most of Europe. **Germany**
  specifically restricts decoding/disclosing non-public transmissions
  under §89 TKG, and several EU members have similar rules. Same
  caveat that already applies to Iridium reception.
- **Maintenance.** Classic Aero has been stable for ~25 years and
  unlikely to change soon, but Inmarsat is migrating safety services
  to **Inmarsat Iris / SwiftBroadband-Safety** — a new air interface
  JAERO does NOT decode. Long term, Classic Aero traffic may decline.
- **Licensing.** libacars and inmarsat-sniffer are **GPL-3.0**. JAERO
  core is MIT. Pulling in inmarsat-sniffer's already-ported C++ chain
  is the fastest path but **forces GPL-3 on the whole firmware**.
  Pulling directly from JAERO (MIT) and reimplementing the
  Qt-stripping work is more effort but preserves licensing flexibility.

## 6. Recommendation

**Worth doing as a Phase 5 extension, with caveats.** Two factors make
this a good fit:

1. The same RTL-SDR Blog L-band patch antenna works for both Iridium
   and Inmarsat — no new antenna in the BOM.
2. inmarsat-sniffer already proves a Qt-stripped, GNU-Radio-free port
   of JAERO's DSP exists. The hardest reverse-engineering work is
   done; the remaining job is embedded portability and integration.

The factors arguing against bundling: a different SAW filter is needed
(or a compromise broadband frontend), GPL-3 licensing of the cleanest
reference code, and the geostationary-vs-LEO link budget makes UX
hardware-dependent in a way Iridium isn't.

**Recommended on-ramp** (smallest viable steps, each independently
shippable):

1. **FFT-only detection mode** — tune to 1545 MHz, show energy on the
   existing detector. Confirms RF chain works end-to-end before any
   DSP work. ~1 weekend.
2. **MSK demod + sync-word lock for 600/1200 bps P-channel** — decode
   raw symbols to a UDP stream that JAERO-on-PC can consume via its
   existing UDP input. Validates against the reference decoder
   without writing the framing layer. ~2–3 weeks.
3. **AeroL framing + libacars on-device** — ESP32-P4 produces decoded
   ACARS messages directly. ~2 weeks.
4. **Optional Phase 5b: 10.5k OQPSK + Viterbi** — only if 5a is well-
   received and CPU/RAM headroom allows.

Keep it in the same repo — the worker pipeline, USB transport, and
detector framework are highly reusable. Gate it behind a build-time
flag (`CONFIG_INMARSAT_AERO_ENABLED`) so users without the SAWbird+ iO
aren't paying for unused code.

## Verdict

Inmarsat Classic Aero P-channel is **technically straightforward to
add**: well-documented modulation, plaintext, continuous (no burst
hunting), DSP already ported once to plain C++. The main gating factor
is **RF frontend** — the SAWbird+ IR currently in BOM doesn't pass
1545 MHz cleanly; SAWbird+ iO swap (or a dual-band design) is required
before any decoding work pays off. With a 4–6 week MVP for 600/1200 bps
decoding and existing ground truth from JAERO, this is a good Phase 5
extension. **Confidence:** medium-high on technical effort; medium on
real-world reception quality (depends on antenna placement); high
that decoded output is useful given ACARS plaintext rate.
